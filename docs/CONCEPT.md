# Atrium — концепция среды координации ИИ-агентов

Atrium — это не каталог с чат-ботом. Это **цифровая среда**, в которой агенты закупки и поставки ведут сделку как стороны, а площадка держит общее состояние: партии, мандаты, документы, сроки и рейтинг. Человек задаёт политику и подписывает необратимые действия (деньги и товар). Агенты делают остальное.

Прототип: [http://127.0.0.1:3000](http://127.0.0.1:3000) · схема агентов — `/office/flow` · живой прогон — `/demo` · контроль — `/trust`.

---

## 1. Зачем это рынок, а не ещё один ERP

B2B-закупка партии — это не «положить в корзину». Это запрос предложения в мессенджере, таблица в Excel, звонок на склад, счёт в почте, закрывающие, приёмка, претензия. Люди копируют одни и те же числа между системами. Ошибки стока, срыв срока и просрочка оплаты — норма, не исключение.

**Целевые пользователи и боль**

| Роль | Что болит сейчас | Что даёт среда агентов |
|---|---|---|
| Закупщик / категория | Сбор КП, торг, сверка кратности и сертификатов | Свободный текст → комнаты с предложениями в мандате |
| Коммерция поставщика | Ответить на 20 заявок, не продать ниже пола | Агент держит маржу, наличие, самовывоз или доставку |
| Казначейство | Не отпускать груз без аванса, ловить просрочку | Подтверждение оплаты; оплаты не в срок меняют следующие условия |
| Склад / логистика | Ложный остаток, паллетная кратность, накладная | Резерв партий по готовности, документы в контуре |
| Операции площадки | Разбор «кто виноват» без следа | Журнал, обход агентов, рейтинг только после арбитража |

Человек не торгуется в чате. Он ставит мандат («не ниже 11% маржи», «не выше бюджета заявки») и подтверждает: утвердить, оплатить, принять, эскалировать.

---

## 2. Среда, а не одиночный агент

Среда — это общее состояние плюс протокол. Агенты не вызывают друг друга «как сервисы». Они совершают **действия** в общем контуре сделки:

```
Заявка → Предложение → Встречное → Согласие | Отказ
         ↓ (человек)
      Утверждение → Аванс → Резерв → Отгрузка → Приёмка → Остаток
         ↓ (срыв)
      Претензия → Обход → Принятие | Эскалация → Решение площадки
```

Каждое действие либо меняет сделку/заказ, либо отклоняется движком мандата. Языковая модель **не** является стороной протокола: она только разбирает свободный текст и переписывает реплики. Цену, количество, статус, резерв партий считает детерминированный движок.

Это важно для доверия: модель может галлюцинировать формулировку, но не может «уступить ещё 3%» мимо пола.

## 3. Архитектура

```
┌─────────────────────────────────────────────────────────────┐
│  Принципалы (люди)                                           │
│  мандат · утверждение · оплата · приёмка · эскалация         │
└───────────────────────────┬─────────────────────────────────┘
                            │ подтверждения
┌───────────────────────────▼─────────────────────────────────┐
│  Агенты сторон                                               │
│  закупка (запрос, встречное)  ↔  поставка (предложение, пол) │
└───────────────────────────┬─────────────────────────────────┘
                            │ сценарий S1 / S2 / S3
┌───────────────────────────▼─────────────────────────────────┐
│  Оркестратор площадки                                        │
│  разложить задачу → назначить роли → ждать человека или факт │
└───────────────┬─────────────────────────────┬───────────────┘
                │                             │
     ┌──────────▼──────────┐       ┌──────────▼──────────┐
     │ Движок мира         │       │ Модель (по желанию) │
     │ подбор, упаковка,   │       │ разбор заявки,      │
     │ пол цены, резерв,   │       │ формулировки        │
     │ сроки, рейтинг      │       │ без смены чисел     │
     └──────────┬──────────┘       └─────────────────────┘
                │
     ┌──────────▼──────────┐
     │ Доверие и арбитраж  │
     │ поставки и оплаты   │
     │ в срок, претензии   │
     └─────────────────────┘
```

Четыре слоя не смешиваются. Оркестратор не торгуется. Агент поставки не списывает деньги. Модель не двигает статусы. Площадка не бьёт рейтинг в момент сигнала.

Код: `src/lib/scenarios.ts` (роли и сценарии), `src/lib/langflow-graph.ts` (граф), `agents.ts` (подбор и торг), `llm-agents.ts` (голос), `fulfillment.ts` (исполнение), `ops.ts` + `trust.ts` (срыв), `effectiveness.ts` (оценка). Интерактивная схема — `/office/flow`. Те же узлы как компоненты Langflow — каталог `langflow/`.

## 4. Модель взаимодействия

Агенты получают **роль + мандат + срез мира**, а не «промпт купи что-нибудь».

| Роль | Видит | Может | Не может |
|---|---|---|---|
| Оркестратор | сценарий, статусы задач | назначить следующий шаг | менять цену |
| Парсер | сырой текст | структурировать потребность | выдумать объём/бюджет, если их нет |
| Подбор | каталог, партии, доверие | открыть до 3 комнат | зарезервировать склад |
| Агент закупки | мандат покупателя, предложения | отвечать встречным в мандате | утвердить сделку, заплатить |
| Агент поставки | мандат продавца, свободные партии | предложить, уступить до пола | продать ниже маржи, отгрузить без аванса |
| Движок мандата | полы, кратность, бюджет | округлить объём, пол цены, статус | «пойти навстречу» мимо правил |
| Исполнение | утверждённая сделка | резерв, накладная, УПД | ехать без оплаты аванса |
| Инциденты | факт на заказе | предложить обход | ударить рейтинг |
| Площадка | документы в контуре | арбитраж, изменение рейтинга | верить устным договорённостям |

Распределение задач — по **сценариям**, не по свободному диалогу:

1. **S1 Закупка партии** — разбор → подбор → торг нескольких поставщиков параллельно → рекомендация → подтверждение человека.
2. **S2 Исполнение** — счёт → резерв → комплектация → отгрузка → приёмка → остаток.
3. **S3 Срыв** — факт → обход агента → 7 дней сторон → иначе арбитр площадки.

Параллелизм в S1: три агента поставки отвечают независимо, агент закупки ведёт три комнаты, оркестратор выбирает лучшее согласие по оценке.

## 5. Безопасность, доверие, контроль

**Политика, не просьба.** Мандат — жёсткое ограничение движка: пол цены, маржа, предоплата, бюджет, кратность упаковки. Нарушить его репликой нельзя.

**Разделение способностей.** Агенты предлагают. Люди подписывают деньги и товар. Площадка меняет рейтинг.

**Песочница модели.** Если перепись реплик вернула другой набор фраз или Ollama молчит — остаются шаблонные реплики движка. Числа из разбора заявки не затирают уже найденные.

**Журнал.** Каждое действие (подбор, встречное, подтверждение, обход, арбитраж) пишется в журнал. Это контроль постфактум и материал для оценки агентов.

**Двустороннее доверие.** Не звёзды витрины, а отгрузки в срок, оплаты в срок, доля претензий, доля срывов. Просрочка оплаты поднимает аванс на следующих партиях. Удар по баллу — только после решения площадки.

**Доказательная претензия.** Без факта в заказе (накладная, УПД, акт) эскалация не защищает сторону.

## 6. Оценка эффективности агентов

Считаем не «насколько красноречива модель», а **вклад в контур**:

| Показатель | Смысл |
|---|---|
| Доля согласованных комнат | агенты находят пересечение мандатов |
| Соблюдение пола цены | все сделки с ценой не ниже пола |
| Оценка подбора | наличие, срок, город, доверие |
| Доля авто-обходов | инциденты закрыты без арбитража |
| Подтверждений человека на цикл | сколько необратимых кликов осталось (цель — 3–4, не 40 писем) |
| Поставки и оплаты в срок | экономические последствия поведения, не лайки |

Живой расчёт: `src/lib/effectiveness.ts`, экран `/trust`.

---

## 7. Что показывает прототип

Рабочий контур в браузере (`localStorage`). Ollama опциональна: без неё сценарий идёт на шаблонах движка.

- Свободный текст → заявка → торг в комнатах → утверждение → аванс → резерв → накладная и УПД → приёмка → остаток.
- Срыв: агент предлагает зачёт, довоз или замену; рейтинг бьёт только Atrium.
- `/demo` прогоняет S1→S2→S3 без ручной навигации и явно показывает подтверждения человека.

Сознательно не в контуре: эквайринг, ЭДО с ФНС, вторая фура как отдельная отгрузка.
