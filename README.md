# Atrium

B2B-площадка как **среда координации ИИ-агентов**: агенты ищут партии и торгуются в мандате, люди утверждают оплату и приёмку. Реплики пишет локальный [Ollama](http://127.0.0.1:11434); цены, кратность упаковки, резерв партий, сроки и рейтинг — детерминированный движок.

## Установка

Прототип крутится локально. Базы, Docker, `.env` и облачные ключи **не нужны**: каталог и сделки живут в браузере (`localStorage`, ключ `atrium-marketplace-v4`). Ставить два слоя — по нарастающей.

| Слой | Зачем | Без него |
|---|---|---|
| Node 20+ и `npm install` | кабинеты, демо-прогон, движок цен, схема агентов | ничего не стартует |
| Ollama + модель | живые формулировки и доразбор заявки | шаблоны движка, числа те же |

### 1. Репозиторий и Node

Нужен **Node 20 или новее** (в `package.json` — Next 16). Проверка: `node -v`. Если меньше 20 — [nvm](https://github.com/nvm-sh/nvm) или пакет с [nodejs.org](https://nodejs.org/). `npm` идёт вместе с Node.

```bash
git clone git@github.com:kobyzev-yuri/ai_mkt.git
cd ai_mkt
npm install
```

`npm install` ставит зависимости из `package-lock.json` в `node_modules/` (каталог в git не коммитится). Сеть нужна только на этот шаг. Повторять при каждом запуске не надо — только после `git pull`, если менялся lock-файл.

Скрипты `./start-demo.sh` и `./start-marketplace.sh` исполняемые в репозитории; если git снял бит: `chmod +x start-demo.sh start-marketplace.sh`.

### 2. Ollama — голос, не цены (необязательно)

Движок **сам** считает пол, потолок, кратность и статус. Ollama только: (а) дополняет разбор свободной фразы, не затирая уже найденные числа; (б) переписывает реплики в комнатах. Если демона нет или модель не скачана — сценарий идёт на правилах `parse-need.ts` и шаблонных текстах. Демо-прогон на `:3001` от Ollama не зависит.

```bash
# Linux: https://ollama.com/download — или:
curl -fsSL https://ollama.com/install.sh | sh

ollama serve                          # если не поднялся как сервис; порт 11434
ollama pull qwen2.5:14b               # штатная модель прототипа
# мало RAM (~8 ГБ):  ollama pull qwen2.5:7b
ollama list                           # имя модели должно совпасть с выбором в /office/settings
```

Сервер должен отвечать на [http://127.0.0.1:11434](http://127.0.0.1:11434). Другой хост: переменная `OLLAMA_HOST` (см. `src/lib/ollama.ts`). Модель 14B — порядка 9 ГБ на диске и столько же в VRAM/RAM при работе.

## Запуск

Два **отдельных** контура: демо-прогон и кабинеты. Разные порты, разный кэш Next (`.next-demo` / `.next`). **Не открывайте оба в одной вкладке** — `localStorage` общий, режимы смешаются.

### Демо-прогон

Это не маркетплейс и не страница `/demo` на порту 3000 (там редирект на вход). Отдельный процесс: без логина, без кабинетов. Показывает автоматизацию продавец ↔ покупатель целиком: сценарии S1 (закупка) → S2 (исполнение) → S3 (срыв и обход). Партии уже на витрине, как после выгрузки 1С. Заявка зашита: 50 000 крафт-коробок в Казань, бюджет 2,1 млн (Кофейня Холдинг).

```bash
./start-demo.sh
# то же: npm run demo
```

Откройте [http://127.0.0.1:3001/demo](http://127.0.0.1:3001/demo) и нажмите **«Запустить прогон»**.

Что смотреть: разбор фразы → поиск партий → торг в мандате (числа считает движок) → четыре подтверждения человека (утвердить, аванс, приёмка, остаток) → инцидент «срыв отгрузки» и обход без удара по рейтингу. Ollama не обязательна: без неё идут шаблоны движка. Любой другой путь на `:3001` редиректит на `/demo`.

Остановка: Ctrl+C в том терминале. Кнопка сброса на экране чистит прогон, не кабинеты `:3000`.

### Маркетплейс (кабинеты)

Живые роли: заявка `/rfq`, адаптер 1С, комнаты, заказы, контроль. Вход карточками участников.

```bash
./start-marketplace.sh
# то же: npm run market
```

Откройте [http://127.0.0.1:3000/login](http://127.0.0.1:3000/login). Пароль на карточке, например ТехСтрой `1112`, СеверПак `2222`, владелец площадки `0000`. Схема агентов — [`/office/flow`](http://127.0.0.1:3000/office/flow) после входа владельца.

| Скрипт | Порт | Кэш | Что это |
|---|---|---|---|
| `./start-demo.sh` | 3001 | `.next-demo` | Автопрогон S1→S3, без входа |
| `./start-marketplace.sh` | 3000 | `.next` | Кабинеты и пароли на карточках |

## Схема агентов

Граф ролей — экран [`/office/flow`](http://127.0.0.1:3000/office/flow) после входа владельца (`0000`). Это документация контура в том же приложении: узлы — роли, рёбра — действия протокола (S0 выгрузка, S1 закупка, S2 исполнение, S3 срыв). Сделки считает TypeScript, не внешний холст. JSON графа можно скачать с экрана (`src/lib/agent-graph.ts`).

```
браузер  →  Next.js (/office/flow, /buy, /api/rfq)
                │
                └─ движок сделок (TypeScript) — каталог, мандат, localStorage
```

## Контур одной фразой

Поиск свободных партий → согласование в мандате → счёт на аванс → резерв партии → накладная и УПД → приёмка → остаток. При срыве агент предлагает обход, рейтинг бьёт только площадка.

Человек подтверждает четыре шага: утвердить, оплатить аванс, принять, оплатить остаток. Остальное делают агенты по сценариям S1–S3.
